# MCP サーバーとして、自分のメモの検索を Claude から呼べるようにする

[前のページ](./semantic-note-search)で、手元のメモを「意味」で検索するコマンドを作りました。ただ、そのコマンドは、自分でターミナルを開いて実行するものでした。このページでは、同じ検索を MCP サーバーにして、**Claude が会話の中で自分から呼べる道具**にします。

つなぐ前と後で、変わるのは次の点です。

| | つなぐ前 | つないだ後 |
|---|---|---|
| 「前にあれをどう決めたっけ」と聞く | 自分でコマンドを実行し、結果を会話に貼り付ける | Claude が、答える前に自分でメモを検索して、根拠つきで答える |
| 別のプロジェクトの会話で使う | コマンドの場所を毎回伝える必要がある | どの会話でも同じ道具が使える |
| 検索の待ち時間 | 実行のたびに、モデルの読み込みで十数秒かかる | モデルをサーバーが持ち続けるので、読み込みは最初の 1 回だけ |

## この記事で分かること

- 既存の検索処理を、MCP の道具に包む方法
- Python の公式ライブラリ `mcp` を使ったサーバーの最小の形
- 標準出力に書いてはいけない、という stdio 方式の決まり
- 作ったサーバーを、どのプロジェクトからも使えるように登録する方法
- Claude に「いつ検索するか」を伝える方法
- 実際に Claude が道具を使うことの確かめ方

## 用語の整理

| 用語 | 意味 |
|---|---|
| MCP サーバー | Claude に「道具（ツール）」を提供するプログラム。詳しくは [07. MCP とコネクター](../claude-code/07-mcp-and-connectors) |
| stdio（標準入出力） | 自分の PC で動かす MCP サーバーが、Claude と文字のやり取りをするための口。標準入力で受け取り、標準出力で返す |
| `mcp`（Python ライブラリ） | MCP サーバーを作るための公式のライブラリ。通信の細かい決まりを肩代わりしてくれる |
| ユーザー設定（user scope） | Claude Code の登録先のうち、どのプロジェクトでも有効になるもの。反対に、特定のプロジェクトだけで有効にする登録先もある |

## 前の MCP 記事との違い

[08. MCP サーバーを自作する](../claude-code/08-build-an-mcp-server)では、カレンダーの予定を読むサーバーを作りました。そのときは、JSON-RPC のメッセージを自分で読み書きしました。通信の仕組みを理解するには良い方法でした。

今回は、公式ライブラリ `mcp` を使います。道具にしたい関数を 1 つ書いて、印を付けるだけで済みます。通信の細かい部分はライブラリが担当します。

## 作る道具

道具は 1 つだけです。

| 項目 | 内容 |
|---|---|
| 名前 | `search_notes`（メモの意味検索） |
| 受け取るもの | 探したい内容を表す文章（`query`）と、返す件数（`limit`。1〜10 件、省略すると 5） |
| 返すもの | 意味の近い順に、スコア、ファイルの場所、本文の冒頭（500 文字まで） |
| できないこと | メモの作成、変更、削除（読み取り専用と宣言する） |

## コード

検索の中身は、前のページで作った処理をそのまま使います。ここでは、MCP に包む部分を示します。

```python
from mcp.server.mcpserver import MCPServer
from mcp_types import ToolAnnotations

server = MCPServer("notes-search", instructions="ユーザーのメモを意味で検索する。...")


@server.tool(title="メモの意味検索", annotations=ToolAnnotations(readOnlyHint=True))
def search_notes(query: str, limit: int = 5) -> str:
    """メモを、意味の近い順に検索する。

    Args:
        query: 探したい内容を表す文章
        limit: 返す件数。1 から 10 まで。省略すると 5
    """
    query, limit = validate_args(query, limit)  # 空の query などははじく
    return format_results(search(query, limit))  # 検索して、読みやすい文章にする


server.run()  # 標準入出力で Claude と通信する
```

仕組みのポイントは 3 つです。

- 関数の**名前、引数の型、説明文（docstring）が、そのまま道具の説明として Claude に渡されます**。説明文は、Claude が「いつ使うか」を判断する材料になるので、丁寧に書きます
- `readOnlyHint=True` は、「この道具はデータを変更しない」という宣言です
- 入力が不正なとき（空の文章など）は、例外を出します。ライブラリがそれをエラーの結果として Claude に返します

## 注意点

### 標準出力に書いてはいけない

stdio 方式では、**標準出力は Claude との通信専用**です。`print()` で何かを書くと、通信のメッセージが壊れて、サーバーが使えなくなります。メッセージを残したいときは、標準エラー出力に書きます。

### `mcp` ライブラリの 2 系では、名前が変わっている

`pip install mcp` で入る最新版（今回は 2.3.0）では、サーバーのクラス名が `FastMCP` から `MCPServer` に変わっていました。インターネット上の古い記事の `from mcp.server.fastmcp import FastMCP` は、そのままではエラーになります。

```text
No module named 'mcp.server.fastmcp'. This is mcp 2.x, where FastMCP was renamed to MCPServer ...
```

エラーメッセージが、移行ガイドの場所も案内してくれます。古いコードを動かしたいときは、`mcp<2` のように版を指定する方法もあります。

### モデルの読み込みは、裏で先に進める

埋め込みモデルの読み込みには十数秒かかります。サーバーの起動時に読み込み終えてから接続を受け付けると、Claude 側の接続が遅れるおそれがあります。そこで、サーバーを先に立ち上げ、モデルは別のスレッドで読み込みます。

### 検索のたびにデータベースへつなぎ直す

接続を使い回すと、待機中に切られたあとの最初の検索が失敗するおそれがあります。検索のたびにつなぎ直すことにして、確実さを優先しました。

## テストの工夫

本物の検索には、モデルとデータベースが必要です。テストでは、**検索する部分を関数として外から渡せる作り**にしておき、偽の検索関数を差し込みます。

```python
server = build_server(fake_search)  # 偽の検索関数を渡す
tools = await server.list_tools()   # 道具が見えるか
result = await server.call_tool("search_notes", {"query": "経緯", "limit": 2})
```

これで、モデルもデータベースも使わずに、次の 3 点を確かめられます。

- 道具が 1 つだけ見えること
- 読み取り専用の宣言があること
- 引数が検索関数に正しく渡ること

## Claude Code に登録する

ユーザー設定に登録すると、どのプロジェクトの会話でも使えます。

```bash
claude mcp add --scope user notes-search -- /path/to/venv/bin/python /path/to/scripts/notes_mcp_server.py
```

```bash
claude mcp list
```

一覧に `notes-search: ... ✔ Connected` と出れば、接続できています。すでに開いている会話には反映されないので、新しい会話を始めてください。

## 「いつ検索するか」を Claude に伝える

道具があっても、使うように指示がなければ、Claude は検索せずに答えてしまうことがあります。そこで、ユーザー全体の指示ファイル（`~/.claude/CLAUDE.md`）に、次のような内容を書きました。

- 過去に決めたこと、設定の経緯、以前に調べた内容が関係しそうな質問では、答える前に 1 回検索する
- 単純な作業や、会話の中で完結する質問では検索しない
- 結果にパスワードや鍵のような値が混ざっていたら、そのまま書き写さない

## 実際に動かして確かめた結果

別のプロセスで Claude を 1 回だけ起動し、次のように質問しました。

```bash
claude -p "データベースのバックアップについて、私は過去にどう考えていると伝えていたか、簡潔に教えて。" \
  --allowedTools "mcp__notes-search__search_notes"
```

`-p` は、1 回だけ質問して結果を返す起動方法です。`--allowedTools` で、この道具を許可しています。

Claude は 3 ターンのうちに `search_notes` を呼び出し、メモの記述を根拠にして答えました。「方針を決めた記録は見当たらない」と、見つからなかったことも正直に答えています。さらに、「日記に書かれた事実の記録」と「Claude がまとめたノート」と「あなた自身の発言」を区別して説明しました。

| 項目 | 結果 |
|---|---|
| サーバーへの接続 | 約 0.3 秒 |
| 最初の検索 | 約 12 秒（接続の直後に呼んだので、モデルの読み込みの途中だったためと考えられる） |
| 2 回目の検索 | 約 4 秒（データベースへの接続を含む） |
| 空の文章での検索 | エラーとして返る |

2 回目でも 4 秒かかっているのは、検索のたびに遠隔のデータベースへつなぎ直しているためだと考えています（この内訳は、まだ測っていません）。

## 試して分かったこと・まだ確かめていないこと

- 検索を道具にすると、「自分で実行して貼り付ける」手間がなくなり、**メモを根拠にした答え**が普通の会話で得られるようになりました
- 見つからなかったときに「ない」と答えてくれるかどうかは、道具の説明文と指示の書き方に左右されます。今回は期待どおりでしたが、1 回の確認です
- 確かめていないこと：Windows での動作、長い期間使ったときに Claude がどのくらいの頻度で検索するか、検索結果のメモに秘密の値が混ざっていた場合の振る舞い

## まとめ

- 既存の処理は、関数を 1 つ書いて印を付けるだけで MCP の道具になる
- stdio 方式では、標準出力に書かない。モデルの読み込みなど重い処理は、裏で進める
- テストでは、重い部分を差し替えられる作りにしておくと、モデルなしで確かめられる
- 道具を作っただけでは使われないことがある。「いつ使うか」を指示ファイルに書いておく
- 動いたかどうかは、別プロセスで Claude を 1 回起動して、道具を使わせて確かめられる
