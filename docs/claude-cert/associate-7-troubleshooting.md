# Associate 分野 7：トラブルシューティングと最適化

[Associate – Foundations](./associate) の出題分野 7「トラブルシューティングと最適化」（Troubleshooting and Optimization）を、試験ガイドの項目ごとに見ます。比重は 10% です。

トラブルシューティングは、うまくいかない原因を突き止めて直すことです。最適化は、同じ結果をより少ない手間や費用で、またはより良い結果を同じ手間で得られるようにすることです。

## この分野の項目

試験ガイドは、この分野について 3 つの項目を挙げています。日本語版の試験ガイド（Version 1.0）の言い方に合わせ、短くまとめました。

| 番号 | 項目 |
|---|---|
| 1 | 期待どおりに動かないプロンプトや、質の低い出力の問題を特定し、診断し、解決する |
| 2 | フィードバックと結果をもとに、やり方を調整する |
| 3 | 効率と効果を高めるために、ワークフローを最適化する |

この分野で使う言葉です。

| 日本語 | 英語 | 意味 |
|---|---|---|
| ステアラビリティ | steerability | 指示によって、AI の出力をどこまで思いどおりに導けるか |
| 推論のドリフト | reasoning drift | 何段階もの推論で、初めの小さな誤りが積み重なってずれていくこと |
| 文言優先 | letter-over-spirit | 指示の文字どおりには従ったが、指示の意図は満たしていないこと |
| おもねり | sycophancy | AI が、利用者の考えや枠組みに安易に同意してしまうこと |
| チェックポイント | checkpoint | 作業の途中で、結果を確かめるために止める場所 |
| 評価（eval） | evaluation | 自分の作業で Claude がどのくらいうまくできるかを、決まった例で試して確かめること |

## 項目 1　問題を特定し、診断し、解決する

- **要点**
  - 直す前に、**何が原因か**を見分ける。AIの能力と限界のコースは、AI の特性を 4 つに分けている。
    - **次トークン予測**：もっともらしく聞こえるものを作る
    - **知識**：学習したことを知っている
    - **ワーキングメモリ**：コンテキストウィンドウの中にあるものに注意を向ける
    - **ステアラビリティ**：いちばん強い指示に従う
  - 実際の失敗の多くは、2 つの特性が重なって起きる。どの 2 つかが分かれば、直し方が決まる。

| 症状 | 重なっている特性 | 直し方 |
|---|---|---|
| 具体的な数字、名前、引用が事実と違う（ハルシネーション） | 次トークン予測 ＋ 知識 | 具体的な内容を、元の資料や信頼できる情報源で確かめる |
| 長い会話で、前に伝えた条件が守られなくなる | ワーキングメモリ ＋ ステアラビリティ | 大事な条件を伝え直す。新しいチャットで始める |
| 計算や論理の正確さが要る作業で誤る | ステアラビリティの限界 | コード実行（計算をプログラムに任せる）を使う |
| 自分の考えに、Claude がすぐ同意する | おもねり | 反論や別の見方を、はっきり求める |

  - **ステアラビリティの得意と苦手**：短く、具体的で、確かめられる指示（形式、長さ、役割）は得意。長い推論の連鎖、抽象的であいまいな指示、計算や論理の正確さは苦手。
  - **文言優先**のとき（指示は守られたが意味のない結果）は、**目的を書き足す**。指示を強い言葉で繰り返しても、ずれは埋まらない。
    - 例：「短くして」だけでなく、「短くして。目的は、2 ページ目の大事な発見まで、役員に読み続けてもらうこと」。
  - **推論のドリフト**には、途中に**チェックポイント**を入れる。たとえば「ステップ 2 の結果を見せてから続けて」。
- **公式の教材**
  - AIの能力と限界「特性が衝突するとき」の「重要なポイント」（診断のペアと、直し方：具体的な内容を確かめる、コンテキストを伝え直す、コード実行に任せる、反論を促す）。
  - AIの能力と限界「ステアラビリティ」の「重要なポイント」。
  - Claude 101 レッスン 3「より良い結果を得る」の「よくある課題とその解決法」（困りごとと直し方の表は、[分野 1](./associate-1-prompting) の項目 3 にまとめた）。
- **試験での見分け方**：症状から原因を選び、原因に合う直し方を選ぶ。「同じ指示を、より強い言葉で繰り返す」「何も変えずに送り直す」は、多くの場合、正解ではない。
- **紛らわしいもの**：出力が悪いときに、すぐ「モデルを上位に変える」のは早い。コンテキストの不足、あいまいな指示、古い資料など、プロンプトや設定の原因を先に疑う。

## 項目 2　フィードバックと結果をもとに、やり方を調整する

- **要点**
  - **記述・評価のループ**を回す。
    1. **記述する**：成果物、進め方、振る舞いをはっきり伝える
    2. **評価する**：成果物そのもの、Claude の進め方、Claude の振る舞いを見る
    3. **改善する**：うまくいったこと、いかなかったことを伝え、記述を直して、また頼む
    4. **統合する**：自分の知識と判断を加え、何を残し、直し、捨てるかを決め、最終的な成果物に責任を持つ
  - フィードバックは**具体的に**する。「短くして」より「最初の 2 段落を消して、結論を行動につながる形にして」。
  - **結果で判断する**：答えの分かっている例（5〜10 個）で試し、自分の結果と比べる。足りないところは、コンテキストや例を足して直す。何度直してもたどり着けない作業は、Claude に任せない。
  - 調べて分かったこと（足すべき情報、限界）は書き留め、次の作業の指示に入れる。
- **公式の教材**
  - AI活用力「記述・評価のループ」の演習の「ステップ3」。
  - Claude 101 レッスン 3「より良い結果を得る」の「反復の考え方」「ワークフローに合わせたClaudeの評価」。
- **試験での見分け方**：一度の結果で「使える」「使えない」と決める選択肢より、例で試し、直して、また試す選択肢を選ぶ。
- **紛らわしいもの**
  - 会話の中で Claude に伝えるフィードバックと、高評価・低評価のボタンで Anthropic に送るフィードバックは別のもの。ボタンは、その会話の Claude の答え方を直すものではない（ボタンのデータの扱いは、[分野 6](./associate-6-governance) の項目 2）。
  - Claude は会話の中の訂正から学習しない。次の会話でも直してほしいことは、プロジェクトの指示やナレッジに残す（[分野 5](./associate-5-configuration-knowledge) の項目 4）。

## 項目 3　ワークフローを最適化する

- **要点**：繰り返しや、むだな手間を見つけて、合う機能に置き換える。

| むだ | 置き換える機能 |
|---|---|
| 毎回、同じ資料と指示を貼っている | プロジェクト（ナレッジと指示） |
| 毎回、同じ手順を説明している | スキル |
| ほかのアプリから、コピーして貼り付けている | コネクター |
| 決まった時間に、同じ作業を頼んでいる | 作業を任せる機能の、定期的に行うタスク（[分野 4](./associate-4-workflow-integration) の項目 4） |
| 簡単な作業に、上位のモデルや高い設定を使っている | 作業に合うモデルと設定（[分野 3](./associate-3-product-model-selection) の項目 3） |
| 長い会話を、新しい話題にも使い続けている | 新しいチャットで始める |

  - 使用量を節約する方法：新しい話題は新しいチャットで始める。使わないツールとコネクターは切る（多くのトークンを使う）。決まった作業は低い設定（effort）で行う。プロジェクトの使わないファイルは消し、指示は短くする。
  - リサーチ機能は、情報源を多く調べるので、使用量の上限に早く近づく。1〜2 の情報源で足りる調べものは、ウェブ検索で済ませる。
- **公式の教材と公式ドキュメント**
  - ヘルプセンター「How do usage and length limits work?」（使用量の上限に近づかないための工夫）。
  - ヘルプセンター「Use research on Claude」（リサーチは使用量の上限に早く近づく）。
  - Claude 101 レッスン 5・7・8（プロジェクト、スキル、コネクター）。
- **試験での見分け方**：「効率」が問われたら、繰り返しを設定に移す選択肢を選ぶ。「効果」が問われたら、出力の質を上げる選択肢（コンテキストを足す、例で試す、人の確認を入れる）を選ぶ。
- **紛らわしいもの**：効率を上げるために、人の確認を省く選択肢は正解にならない。影響の大きい作業の確認は残す（[分野 2](./associate-2-output-evaluation) の項目 4）。

## 確認問題

すべて自作の問題です。

<QuizQuestion
  :number="1"
  question="Claude に企画書を「もっと短くして」と頼んだところ、文字数は減りましたが、大事な提案が消えて、意味のない文章になりました。最も効果的な次の一手はどれですか。"
  :choices="['「もっと短くして」と、より強い言葉で繰り返す', '短くする目的（例：役員が 1 分で提案の要点をつかめるようにする）を書き足して、もう一度頼む', 'モデルを上位のものに変えて、同じ依頼を送る', '何も変えずに、何回か送り直す']"
  answer="B"
>

指示の文字どおりには従ったが、意図が満たされていない「文言優先」の失敗です。

- **A（誤り）**：指示を強く繰り返しても、ずれは埋まりません。
- **B（正解）**：目的を書き足すと、意図に沿って短くできます。
- **C（誤り）**：原因は、目的が伝わっていないことです。
- **D（誤り）**：足りない情報は、送り直しても補われません。

</QuizQuestion>

<QuizQuestion
  :number="2"
  question="Claude に、5 つの手順を順に踏む売上の予測を頼みました。最後の数字がおかしく、調べると、2 つめの手順の小さな誤りが最後まで引き継がれていました。再発を防ぐ方法として適切なものはどれですか。2 つ選んでください。"
  :choices="['途中の手順の結果を見せてもらい、確かめてから次の手順へ進めるようにする', '計算はコード実行で行うように頼む', '手順をすべて 1 つの文にまとめて、短くする', '「絶対に間違えないで」と指示に書く']"
  answer="A,B"
>

推論のドリフト（初めの小さな誤りが積み重なる）と、計算の正確さの問題です。

- **A（正解）**：途中にチェックポイントを入れます。
- **B（正解）**：計算や論理の正確さが要る部分は、コード実行に任せます。
- **C（誤り）**：途中で確かめられなくなります。
- **D（誤り）**：強い言葉にしても、ドリフトは防げません。

</QuizQuestion>

<QuizQuestion
  :number="3"
  question="毎週月曜に、Slack と Google Drive から先週の議事録をコピーしてチャットに貼り、決まった形の週報を作らせています。毎回、週報の形を一から説明しています。効率を上げる方法として、最も適切な組み合わせはどれですか。"
  :choices="['毎回、さらに詳しく形を説明する', 'コネクターで Slack と Google Drive をつなぎ、週報の手順をスキルにする', '週報の作成をやめて、議事録をそのまま配る', '何か月も同じチャットを使い続け、説明を省く']"
  answer="B"
>

コピーして貼り付ける手間はコネクター、毎回の手順の説明はスキルに置き換えます。

- **A（誤り）**：手間が増えます。
- **B（正解）**：繰り返しを、機能の設定に移しています。
- **C（誤り）**：作業の目的を捨てていて、最適化ではありません。
- **D（誤り）**：会話が長くなり、前の内容に注意が向きにくくなります。使用量も多く減ります。

</QuizQuestion>
