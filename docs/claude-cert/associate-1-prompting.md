# Associate 分野 1：プロンプト作成とタスク実行

[Associate – Foundations](./associate) の出題分野 1「プロンプト作成とタスク実行」（Prompting and Task Execution）を、試験ガイドの項目ごとに見ます。比重は 14% です。

プロンプトは、Claude に送る依頼の文章のことです。この分野は、「どう頼めば、目的に合った出力が得られるか」を問います。

## この分野の項目

試験ガイドは、この分野について 4 つの項目を挙げています。日本語版の試験ガイド（Version 1.0）の言い方に合わせ、短くまとめました。

| 番号 | 項目 |
|---|---|
| 1 | ビジネスや技術の作業のために、効果的なプロンプトを作る |
| 2 | タスク分解の手法で、複雑な依頼を組み立てる |
| 3 | プロンプトを反復的に改良して、出力の品質を高める |
| 4 | タスクの種類（分析、調査、下書き、ブレインストーミング）に合わせて、プロンプトの作り方を変える |

この分野で使う言葉です。

| 日本語 | 英語 | 意味 |
|---|---|---|
| プロンプト | prompt | Claude に送る依頼の文章 |
| コンテキスト | context | 依頼の背景になる情報（目的、読み手、状況、資料など） |
| 制約条件 | constraints | 出力が守るべき条件（形式、長さ、使ってよい情報など） |
| フューショット | few-shot / multishot prompting | 求める出力の例をいくつか見せて、形やトーンをそろえさせる方法 |
| タスク分解 | task decomposition | 大きな依頼を、順番に進められる小さな作業に分けること |
| プロンプトの連鎖 | prompt chaining | 分けた作業を、別々の依頼として順に出し、前の出力を次の依頼に使うこと |
| 記述力 | Description | AI活用力の 4D の 1 つ。AI に、求めるものとやり方を伝える力 |

## 項目 1　効果的なプロンプトを作る

- **要点**
  - Claude 101 は、プロンプトの前に 3 つを考えるよう勧めている。
    - **舞台を整える**：自分の役割、目標、仕事のコンテキスト
    - **タスクを定義する**：書く、分析する、作るなど、Claude にしてほしい行動
    - **ルールを指定する**：スタイル、トーン、形式、見せられる例
  - AI活用力は、記述を 3 種類に分けている。
    - **成果物の記述**：何を作ってほしいか（形式、対象者、スタイル）
    - **プロセスの記述**：どう取り組んでほしいか
    - **パフォーマンスの記述**：やり取りの中でどう振る舞ってほしいか（簡潔か詳細か、批判的か支持的か）
  - 開発者向けのガイドは、Claude を「優秀だが、職場の決まりや流れを知らない新入社員」と考えるよう勧めている。指示を求めるほど具体的に書くほど、結果がよくなる。
  - 指示には**理由**を添える。理由が分かると、Claude は指示の意図を広げて当てはめられる。
  - 形式は、「〜しないで」より「〜にして」と、してほしいことで書く。
- **公式の教材と公式ドキュメント**
  - Claude 101 レッスン 2「Claudeとの最初の会話」の「効果的なプロンプトを書く」。
  - AI活用力「記述力 (Description) を詳しく見る」。
  - 開発者向けドキュメント「Prompting best practices」の「Be clear and direct」「Add context to improve performance」「Control the format of responses」。確かめ方として、「その作業をよく知らない同僚に見せて、迷うなら Claude も迷う」と書かれている。
- **試験での見分け方**：答えが一般的すぎるときは、コンテキスト（対象者、役割、制約）が足りない。選択肢では、具体的な状況と条件を加えたプロンプトを選ぶ。
- **紛らわしいもの**：長いプロンプトがよいプロンプトではない。必要な目的、条件、形式がそろっているかで判断する。

## 項目 2　タスク分解で、複雑な依頼を組み立てる

- **要点**
  - 複雑な作業は、一度に全部を頼まず、**順番のある小さな作業**に分ける。手順の順番や漏れが大事なときは、番号付きの手順で書く。
  - 分けた作業を別々の依頼にして順に出すと、**途中の出力を確かめてから**次へ進める。よく使う形は「下書き → 基準に照らして見直させる → 見直しをもとに直させる」。
  - 一つの依頼の中でも、「まず考えてから答えて」と、考える段階を先に置ける。
- **公式の教材と公式ドキュメント**
  - AI活用力「効果的なプロンプト技法」。6 つの基礎の技法として、コンテキストを提供する、例を示す、制約条件を指定する、複雑なタスクをステップに分割する、AI にまず考えさせる、AI の役割やトーンを定義する、を挙げている。
  - 「Prompting best practices」の「Chain complex prompts」。最近のモデルは多くの段階の推論を自分の中で進められるが、途中の出力を確かめたいときや、決まった流れで進めたいときは、分けて依頼するのが今も役に立つ、としている。
- **試験での見分け方**：「途中の結果を人が確かめたい」「段階ごとに別の基準で見たい」と問題文にあれば、作業を分けて順に依頼する選択肢を選ぶ。
- **紛らわしいもの**：タスク分解（作業を分ける）と、分野 4 の委任力（作業ごとに人と AI のどちらがするかを決める）は別のこと。分解したあとに、だれがするかを決める。

## 項目 3　プロンプトを反復的に改良する

- **要点**
  - 最初のプロンプトで完璧な結果が出ることはまれで、それで構わない。最初の出力は**出発点**として扱う。
  - 直すときは、**具体的に**伝える。「短くして」より、「最初の 2 段落を消して、結論を行動につながる形にして」のほうが効く。
  - 直し方は 3 つある。
    - **追加で質問する**：詳しく、別の角度で、はっきりと
    - **フィードバックする**：よい点とよくない点を伝える
    - **方向を変えるか、やり直す**：大きくずれたら、新しいチャットで、よりはっきりしたプロンプトから始めたほうが早いこともある
  - プロンプトを直したいときは、新しいメッセージを足すより、送ったメッセージを編集して送り直せる。
  - Claude 自身に、プロンプトの改善を手伝ってもらえる。
- **公式の教材**
  - Claude 101 レッスン 2「Claudeの回答を改善する」、レッスン 3「より良い結果を得る」の「よくある課題とその解決法」「反復の考え方」。
  - AI活用力「効果的なプロンプト技法」。AI 自体にプロンプトの改善を手伝ってもらうことを「秘密兵器」と呼んでいる。
- **試験での見分け方**：出力の困りごとと、直し方の組み合わせで判断する。

| 困りごと | 直し方 |
|---|---|
| 答えが一般的すぎる | 対象者、役割、制約などのコンテキストを足す |
| 長すぎる、短すぎる | 長さをはっきり指定する（「2 段落で」「100 語以内で」） |
| 形式が違う | 説明するだけでなく、形式の例を見せる |
| 自信ありげな情報が間違っている | 大事な事実は自分で確かめる。出典を引用させる。ウェブ検索を使う |
| トーンが合わない | トーンを具体的に書く。求める文章の例を見せる |

- **紛らわしいもの**：同じ会話でいくら直しても戻らないときは、直し続けるより、新しいチャットでやり直すほうがよい場合がある（分野 3 の項目 4）。

## 項目 4　タスクの種類に合わせて、プロンプトの作り方を変える

- **要点**：試験ガイドが挙げる 4 つの種類ごとに、プロンプトで特に足すものが違う。

| 種類 | プロンプトで特に足すもの | 合う機能 |
|---|---|---|
| <span class="nowrap">分析</span> | 分析の目的、見てほしい観点、データの説明。答えの分かっている過去のデータで試してから使う | ファイルのアップロード。考える段階（思考モード） |
| <span class="nowrap">調査</span> | 具体的な目標、ほしい章立て、予算や期間などの制約。引用付きを求める | ウェブ検索（少ない情報源ですぐ答えがほしいとき）、リサーチ（多くの情報源をまとめるとき） |
| <span class="nowrap">下書き</span> | 読み手、目的、トーン、長さ、形式。自分の過去の文章を例として見せる | アーティファクト、プロジェクト（同じ指示を何度も使うとき） |
| <span class="nowrap">ブレインストーミング</span> | テーマと制約、ほしい案の数。幅広く出させてから絞る | 会話（ターンごとにやり取りする） |

- **公式の教材**
  - Claude 101 レッスン 10「深掘り調査のためのリサーチ機能」の「効果的なリサーチ機能プロンプトのコツ」（目標を具体的にする、希望する章立てを指定する、制約条件を含める）と、「リサーチ機能をいつ使うか」。
  - Claude 101 レッスン 3 の「ワークフローに合わせたClaudeの評価」（分析は、答えの分かっている過去のデータで試す）。
  - Claude 101 レッスン 3 の「よくある課題とその解決法」（下書きのメールの例で、対象読者、状況、トーンを足している）。
- **試験での見分け方**：問題文の作業が 4 つのどれかを先に見分ける。調査なら情報源と引用、分析なら観点と検証、下書きなら読み手とトーン、ブレインストーミングなら数と幅を足す選択肢を選ぶ。
- **紛らわしいもの**：調査でも、答えが 1〜2 の情報源で足りる、速さが大事、という場合はリサーチ機能ではなくウェブ検索が合う。外の情報が要らない深い推論（計算、論理の分析）なら、思考モードが合う。

## 確認問題

すべて自作の問題です。

<QuizQuestion
  :number="1"
  question="人事担当者が Claude に「新しい在宅勤務制度の案内文を書いて」と頼んだところ、どの会社にも当てはまりそうな一般的な文章が返ってきました。次に送るプロンプトとして、最も効果的なものはどれですか。"
  :choices="['「もっと良い文章にしてください」', '「全社員向けで、来月から週 2 日まで在宅勤務ができること、申請は上司の承認が要ることを伝えたい。丁寧だが堅すぎない文体で、300 字程度にしてください」', '「人事のプロとして、最高の案内文を書いてください」', '同じ依頼を、何回か送り直す']"
  answer="B"
>

答えが一般的すぎるのは、コンテキストが足りないためです。

- **A（誤り）**：何をどう良くするのかが伝わりません。
- **B（正解）**：対象者、伝える内容、トーン、長さを足しています。
- **C（誤り）**：役割を与えても、制度の中身や読み手が分からないままです。
- **D（誤り）**：足りない情報は、送り直しても補われません。

</QuizQuestion>

<QuizQuestion
  :number="2"
  question="Claude に、20 社分の顧客アンケートから改善提案の報告書を作らせます。途中で、分類が正しいかを自分で確かめてから先へ進めたいと考えています。最も適した進め方はどれですか。"
  :choices="['すべての手順を 1 つのプロンプトにまとめ、完成した報告書だけを見る', '「回答の分類」「分類ごとの傾向のまとめ」「改善提案の作成」を別々の依頼にして、各段階の出力を確かめてから次を頼む', 'プロンプトを短くして、Claude にやり方をすべて任せる', '報告書を何回か作らせて、いちばん長いものを使う']"
  answer="B"
>

途中の出力を確かめたいときは、作業を分けて順に依頼します。

- **A（誤り）**：途中の分類を確かめられません。
- **B（正解）**：タスク分解と、プロンプトの連鎖です。
- **C（誤り）**：途中で確かめる手順が入りません。
- **D（誤り）**：長さは、正しさの基準になりません。

</QuizQuestion>

<QuizQuestion
  :number="3"
  question="次の依頼のうち、リサーチ機能よりも、ウェブ検索が適しているものはどれですか。2 つ選んでください。"
  :choices="['取引先の会社の本社の住所を調べる', '競合 5 社の価格、機能、サポートを比べた、出典付きの報告書を作る', '今日の為替レートを確かめる', '新しい市場への参入について、多くの情報源から検証できる報告書を作る']"
  answer="A,C"
>

すぐに分かる具体的な事実で、情報源が 1〜2 つで足りるときは、ウェブ検索が合います。

- **A（正解）**：具体的な事実を手早く知りたい依頼です。
- **B（誤り）**：多くの情報源をまとめる比較なので、リサーチ機能が合います。
- **C（正解）**：網羅性より速さが大事な依頼です。
- **D（誤り）**：多くの情報源をまとめ、引用で検証できる報告書なので、リサーチ機能が合います。

</QuizQuestion>
