# Associate 分野 2：出力の評価と検証

[Associate – Foundations](./associate) の出題分野 2「出力の評価と検証」（Output Evaluation and Validation）を、試験ガイドの項目ごとに見ます。比重は 21% で、7 つの分野の中でいちばん大きい分野です。

## この分野の項目

試験ガイドは、この分野について 6 つの項目を挙げています。分野の名前と項目は、日本語版の試験ガイド（Version 1.0）の言い方に合わせ、短くまとめました。

| 番号 | 項目 |
|---|---|
| 1 | 出力の正確性と網羅性を評価する |
| 2 | ハルシネーション、不整合、バイアスを特定する |
| 3 | ファクトチェックと検証の手法を使う |
| 4 | 人間によるレビューや、追加の検証が必要な場面を判断する |
| 5 | 想定する読み手に合わせて、出力を編集、調整、改良、比較する |
| 6 | 情報を整理、選別し、出力の形式（アーティファクト、インライン、構造化データ）を選ぶ |

この分野で使う言葉です。

| 日本語 | 英語 | 意味 |
|---|---|---|
| 正確性 | accuracy | 書かれている内容が、事実や資料と合っていること |
| 網羅性 | completeness | 必要な内容が、抜けずに入っていること |
| ハルシネーション | hallucination | AI が、事実でない内容を、もっともらしく作ってしまうこと |
| 不整合 | inconsistency | 同じ出力の中や、資料との間で、内容が食い違っていること |
| バイアス | bias | 見方や表現が、一方に偏っていること |
| ファクトチェック | fact-checking | 出力の中の事実を、元の資料や信頼できる情報源で確かめること |
| 引用 | citation | 出力の根拠として、資料の場所や文を示すこと |
| アーティファクト | artifact | claude.ai で、会話とは別の画面に表示される成果物（文書、コード、図など） |
| インライン | inline | 会話の中に、そのまま答えを書くこと |
| 構造化データ | structured data | 表、JSON、CSV のように、決まった形に整えたデータ |

## 項目 1　出力の正確性と網羅性を評価する

- **要点**
  - 評価は 2 つに分けて考える。**正確性**は「書かれていることが正しいか」、**網羅性**は「書かれるべきことが抜けていないか」。
  - 網羅性は、出力だけを読んでも分からない。依頼の内容や元の資料と照らし合わせて、「何が入っているべきか」を先に決めておく。
  - Claude は、新しい出来事について、最新の情報を持っていないことがある。最新の情報が要る作業では、特に確かめる。
- **公式ドキュメント**：ヘルプセンターの「Claude is providing incorrect or misleading responses. What's going on?」。最新の情報がないことと、もっともらしい誤りを作ることが、誤りの例として挙げられている。
- **このサイトでの例**：下の「実際にあった例」の例 2 は、網羅性の問題。
- **試験での見分け方**：「正しいことしか書かれていないが、大事な点が抜けている」出力は、正確でも網羅的ではない。選択肢で「正確性を確かめる」と「網羅性を確かめる」が分かれていたら、場面で問われているのはどちらかを見る。
- **紛らわしいもの**：網羅性は「長いほどよい」ではない。依頼に要らない内容が多いことは、網羅性の高さではなく、項目 6 の「選別」の問題。

## 項目 2　ハルシネーション、不整合、バイアスを特定する

- **要点**
  - **ハルシネーション**：もっともらしい引用や主張が、事実に基づいていないことがある。数字、固有名詞、日付、引用、出典は、特に疑う。
  - **不整合**：出力の前半と後半、表と本文、資料と要約の間で、内容が食い違っていないかを見る。同じ依頼を何回か出して答えを比べ、答えが毎回違う部分は、ハルシネーションの疑いがある。
  - **バイアス**：一方の見方だけを取り上げていないか、特定の人や集団について決めつけた表現がないかを見る。
- **公式ドキュメント**
  - ヘルプセンターの「Claude is providing incorrect or misleading responses. What's going on?」。権威がありそうに聞こえるが、事実に基づかない引用や主張を作ることがある、とされている。
  - 開発者向けドキュメントの「Reduce hallucinations」。同じプロンプトを何回か実行して出力を比べ、食い違いからハルシネーションに気づく方法が「Best-of-N verification」として紹介されている。
- **このサイトでの例**：「実際にあった例」の例 1 は、もっともらしいが古い情報の例。
- **試験での見分け方**：「自信のある書き方をしているから正しい」とは考えない。書き方の自信と、内容の正しさは別のもの。
- **紛らわしいもの**：バイアスの確かめ方は、公式ドキュメントでは手順が見つからなかった。上の「バイアス」の見方は、このサイトでまとめたもの。

## 項目 3　ファクトチェックと検証の手法を使う

- **要点**
  - **元の資料と照らし合わせる**：資料を渡した作業なら、主張ごとに、資料のどこに書かれているかを確かめる。Claude に「主張ごとに、根拠になる資料の文を引用させる」「根拠の文が見つからない主張は消させる」こともできる。
  - **引用を見る**：ウェブ検索を使った答えには、引用と出典のリンクが付く。リンク先の元のページを読み、Claude の要約が元の内容と合っているかを確かめる。
  - **「分からない」と言ってよいと伝える**：分からないときは「分からない」と答えてよい、と先に伝えると、事実でない内容が減る。
  - **渡した資料だけを使わせる**：一般的な知識ではなく、渡した資料だけを使うように指示する。
- **公式ドキュメント**
  - 「Reduce hallucinations」。「分からない」と言ってよいと伝える、引用で根拠を示させる、渡した資料だけを使わせる、などの方法が挙げられている。ただし、どの方法もハルシネーションを完全にはなくせない、と書かれている。
  - ヘルプセンターの「Enable and use web search」。ウェブ検索の答えには引用が付き、自分で出典を確かめられる。大事な判断には、信頼できる情報源を使うよう勧めている。
- **このサイトでの例**：このサイトのページは、公式ドキュメントで事実を確かめてから書き、ページの最後の「確認の記録」に、確かめたドキュメントを書いている。
- **試験での見分け方**：「Claude にもう一度聞いて確かめる」だけでは、検証として弱い。元の資料や、信頼できる情報源と照らし合わせる選択肢を選ぶ。
- **紛らわしいもの**：引用が付いていても、要約が元のページの内容と合っているとは限らない。ヘルプセンターも、元のページには要約に入っていない文脈や詳しい内容があることがある、としている。

## 項目 4　人間によるレビューや、追加の検証が必要な場面を判断する

- **要点**
  - 間違えたときの影響が大きい内容は、人間が確かめる。たとえば、法律、医療、お金、採用など、人の生活や権利に関わる判断。
  - Claude を唯一の情報源にしない。大事な情報は、ほかの情報源と照らし合わせる。
- **公式ドキュメント**
  - ヘルプセンターの「Claude is providing incorrect or misleading responses. What's going on?」。影響の大きい助言は、行動する前に注意して確かめるよう勧めている。
  - 「Reduce hallucinations」。大事な情報は、特に影響の大きい判断では、いつも確かめるよう書かれている。
  - Anthropic の利用規約（Usage Policy。2026 年 11 月 12 日に発効する版）。影響の大きい使い方では、資格のある人が確かめることが求められている。詳しくは、分野 6「ガバナンス、リスク、責任ある利用」のページで扱う。
- **試験での見分け方**：影響の大きさで判断する。社内メモの言い回しを整える作業と、顧客への法律の説明を作る作業では、必要な確認の重さが違う。
- **紛らわしいもの**：「AI を使わない」は、多くの場合、正解ではない。Claude を使ったうえで、人が確かめる手順を入れる選択肢が正解になりやすい。

## 項目 5　想定する読み手に合わせて、出力を編集、調整、改良、比較する

- **要点**
  - 同じ内容でも、読み手によって、言葉の難しさ、長さ、詳しさ、書き方を変える。たとえば、経営層には結論を先に、現場の担当者には手順を細かく書く。
  - 一度で完成させようとせず、出力を読んで、足りないところを指示して直させる。
  - 何通りかの案を出させて比べ、よいところを選ぶ。
- **公式ドキュメント**：読み手に合わせた直し方について、手順を書いた公式ドキュメントは、このページでは確かめていない。出力を次の依頼に使って、確かめたり詳しくしたりする方法は、「Reduce hallucinations」に「Iterative refinement」として紹介されている。
- **このサイトでの例**：このサイトのページは、Claude が下書きし、筆者が読んで分かりにくいところを指摘し、直してから公開している。
- **試験での見分け方**：「読み手」が問題文に書かれていたら、それに合わせて直す選択肢を選ぶ。読み手を考えずに「もっと詳しく」とだけ頼む選択肢は、弱い。
- **紛らわしいもの**：読み手に合わせて言い回しを変えても、事実を変えてはいけない。簡単に言い換えるときに、内容が不正確にならないかを確かめる。

## 項目 6　情報を整理、選別し、出力の形式を選ぶ

- **要点**
  - 読み手に要る情報を選び、要らない情報を省く。
  - 出力の形式を、使い方に合わせて選ぶ。

| 形式 | 向いているもの |
|---|---|
| インライン | 短い答え、その場で読めばよい説明、会話の続き |
| アーティファクト | まとまった長さがあり、それだけで読めて、あとで直したり、会話の外で使ったりするもの（文書、コード、図、小さなツールなど） |
| 構造化データ | ほかのツールに取り込むもの、項目をそろえて比べるもの（表、JSON、CSV など） |

- **公式ドキュメント**：ヘルプセンターの「What are artifacts and how do I use them?」。Claude がアーティファクトを作るのは、内容が大きくてそれだけで完結している（おおむね 15 行より長い）、会話の外で直したり使い直したりしそう、会話の文脈がなくても分かる、あとで見返しそう、という場合とされている。
- **このサイトでの例**：[Claude Code の Artifacts](../claude-code/11-artifacts) のページで、アーティファクトを実際に作っている。
- **試験での見分け方**：「あとで直す」「人に渡す」「ほかのツールで使う」が問題文にあれば、インラインではない形式を考える。
- **紛らわしいもの**：アーティファクトの説明は、上の表は分かりやすくするための目安。Claude がアーティファクトを作るかどうかは、ヘルプセンターの条件で決まる。

## 実際にあった例：このサイトを作る中で

このテーマのページを準備する中で、Claude の出力を確かめて、誤りや抜けが見つかった例です。

| 例 | Claude の出力 | 確かめたこと | 分かったこと | 項目 |
|---|---|---|---|---|
| 1 | 試験の予約を取り消せる期限を、「24 時間前まで」と記録していた | 試験の FAQ の今のページを読み直した | 今は「48 時間前まで」だった。記録したあとで変わったのか、記録したときに読み違えたのかは分からない | 1、2 |
| 2 | 試験ガイドは英語の PDF しかない、と答えた | 試験のページの表示を日本語に切り替えた | 日本語版の試験ガイドがあった。英語の表示のまま探したので、見落としていた | 1、3 |
| 3 | （Claude ではなく、ある問題集の説明）「本番は英語のみ」と書かれていた | 試験の FAQ を読んだ | 試験は英語と日本語で受けられる。公式の情報源と照らし合わせて、誤りに気づいた | 3 |

例 1 と 2 は、どちらも書き方に迷いがなく、読んだだけでは誤りに気づけませんでした。公式のページという元の情報源に戻ったことで、気づけました。

## 確認問題

すべて自作の問題です。

<QuizQuestion
  :number="1"
  question="Claude に、20 ページの社内規程を要約させました。要約に書かれていることは、どれも規程と合っていました。ほかに、まず確かめるべきことはどれですか。"
  :choices="['要約の文章が読みやすいか', '規程の大事な決まりが、要約から抜けていないか', '要約が規程より短くなっているか', 'Claude が自信のある書き方をしているか']"
  answer="B"
>

書かれていることが正しいこと（正確性）は確かめたので、次は、書かれるべきことが抜けていないか（網羅性）を確かめます。

- **A（誤り）**：読みやすさも大事ですが、内容の確かめより後です。
- **B（正解）**：網羅性は、規程と照らし合わせないと分かりません。
- **C（誤り）**：短くなっていても、大事な決まりが抜けていれば役に立ちません。
- **D（誤り）**：書き方の自信は、内容の正しさを示しません。

</QuizQuestion>

<QuizQuestion
  :number="2"
  question="ウェブ検索を使って、ある製品の価格を Claude に調べさせました。答えには出典のリンクが付いています。最もよい確かめ方はどれですか。"
  :choices="['出典のリンクが付いているので、そのまま使う', '同じ質問を Claude にもう一度して、同じ答えが出るか確かめる', '出典のリンク先を開き、価格と、その価格の条件が答えと合っているか確かめる', '答えをもっと短くまとめるように頼む']"
  answer="C"
>

- **A（誤り）**：引用が付いていても、要約が元のページと合っているとは限りません。
- **B（誤り）**：答えの比べ方の一つですが、元の情報源と照らし合わせる確かめ方より弱いです。
- **C（正解）**：元のページには、要約に入っていない条件（税込みかどうか、期間限定かどうかなど）があることがあります。
- **D（誤り）**：短くしても、正しさは確かめられません。

</QuizQuestion>

<QuizQuestion
  :number="3"
  question="人間によるレビューを、特に入れるべき作業はどれですか。2 つ選んでください。"
  :choices="['社内の勉強会の案内の文面を整える', '応募者を書類選考で落とすかどうかの判断材料をまとめる', '会議のメモから、決まったことを箇条書きにする', '顧客に送る、契約の解約条件の説明を作る']"
  answer="B,D"
>

間違えたときに、人の権利や生活、お金に大きな影響が出る作業には、人間が確かめる手順を入れます。

- **A（誤り）**：間違えても影響は小さく、読んで確かめれば十分です。
- **B（正解）**：採用は、人の生活に関わる判断です。
- **C（誤り）**：会議に出た人が読んで確かめれば十分です。
- **D（正解）**：契約の条件は、法律やお金に関わり、誤りが顧客に届きます。

</QuizQuestion>

<QuizQuestion
  :number="4"
  question="毎月使う、30 行ほどの報告書のひな形を Claude に作らせます。あとで自分で直しながら使い続けます。最も向いている出力の形式はどれですか。"
  :choices="['会話の中に、そのまま書かせる（インライン）', 'アーティファクトとして作らせる', '一文ずつ、何回かに分けて答えさせる', 'JSON で出力させる']"
  answer="B"
>

- **A（誤り）**：短い答えには向きますが、あとで直しながら使い続ける成果物には向きません。
- **B（正解）**：まとまった長さがあり、それだけで読めて、あとで直して使い続けるものは、アーティファクトに向いています。
- **C（誤り）**：ひな形がばらばらになり、使いにくくなります。
- **D（誤り）**：ほかのツールに取り込むなら向きますが、人が読んで直す文書には向きません。

</QuizQuestion>
