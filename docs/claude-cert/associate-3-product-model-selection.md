# Associate 分野 3：製品とモデルの選択

[Associate – Foundations](./associate) の出題分野 3「製品とモデルの選択」（Product and Model Selection）を、試験ガイドの項目ごとに見ます。比重は 12% です。

この分野は、「どの機能を使うか」「どのモデルを使うか」「長い会話や資料をどう扱うか」の判断を問います。

## この分野の項目

試験ガイドは、この分野について 4 つの項目を挙げています。日本語版の試験ガイド（Version 1.0）の言い方に合わせ、短くまとめました。

| 番号 | 項目 |
|---|---|
| 1 | Claude の製品機能（プロジェクト、リサーチ、チャット、アーティファクト）を選ぶ |
| 2 | Claude のモデルの種類（Haiku、Sonnet、Opus）を区別する |
| 3 | モデルの選択を、タスクの要件（コスト、速度、品質）に合わせる |
| 4 | コンテキストの制限とメモリを理解し、管理する（やり直す、要約する、保持するタイミング） |

この分野で使う言葉です。

| 日本語 | 英語 | 意味 |
|---|---|---|
| コンテキストウィンドウ | context window | Claude が一度に注意を向けられる情報の範囲。会話、指示、資料がすべてここに入る。AI の「ワーキングメモリ」とも言う |
| トークン | token | Claude が文章を扱う単位。コンテキストウィンドウの大きさや API の料金は、トークンの数で表す |
| プロジェクト | Projects | 専用のチャット履歴、ナレッジ（資料）、指示を持つ作業場所 |
| RAG（検索拡張生成） | retrieval-augmented generation | 資料を全部読み込まず、質問に関係する部分だけを探して取り込む方法 |
| メモリ | memory | 会話から役割や好みなどを覚えて、次の会話でも使う機能 |
| レイテンシ | latency | 依頼してから答えが返るまでの時間 |

## 項目 1　製品機能を選ぶ

- **要点**

| 機能 | 向いている場面 |
|---|---|
| <span class="nowrap">チャット</span> | 一度きりの質問や作業。答えを見ながら、その場でやり取りを進める |
| <span class="nowrap">プロジェクト</span> | 続けて取り組む作業。繰り返し使う資料がある、答え方の要件をいつもそろえたい、チームで同じ土台から作業したい |
| <span class="nowrap">リサーチ</span> | 多くの情報源をまとめた、引用付きの報告書。比較の分析。手作業なら何時間もかかる調査 |
| <span class="nowrap">アーティファクト</span> | 会話の外で使ったり、あとで直したりする、まとまった成果物（文書、コード、図など）。詳しくは[分野 2 の項目 6](./associate-2-output-evaluation) |

  - **プロジェクト**：資料（ナレッジ）とプロジェクトの指示は、そのプロジェクトのすべてのチャットで使われる。チャット同士の会話の内容は、ナレッジに加えない限り共有されない。資料がコンテキストウィンドウの上限に近づくと、有料プランでは RAG に切り替わり、扱える量が最大 10 倍になる。無料のプランでもプロジェクトは作れる（5 つまで）。
  - **リサーチ**：有料プランで使える。ウェブ検索をオンにしておく必要がある。Claude が計画を立て、互いに積み重なる検索を何回も行い、結果をまとめて、主張ごとに出典を付ける。数分以上かかり、使用量の上限に早く近づく。
- **公式の教材と公式ドキュメント**
  - Claude 101 レッスン 5「プロジェクト入門」の「プロジェクトを使うべきとき」「プロジェクトが大規模なナレッジベースを処理する方法」。
  - Claude 101 レッスン 10「深掘り調査のためのリサーチ機能」の「リサーチ機能をいつ使うか」。
  - ヘルプセンター「What are projects?」「Use research on Claude」。
- **試験での見分け方**：「毎回同じ資料と指示を使う」「チームで共有する」ならプロジェクト、「多くの情報源」「出典付きの報告書」ならリサーチ、「1〜2 つの情報源ですぐ分かる事実」ならウェブ検索、を選ぶ。
- **紛らわしいもの**
  - 会話中にアップロードしたファイルは、その会話だけで使われ、プロジェクトのナレッジには入らない。
  - 外の情報が要らない深い推論（計算、論理の分析）には、リサーチではなく思考モードが合う。

## 項目 2　モデルの種類を区別する

- **要点**：3 つの系統の違いを、性能、速さ、費用で押さえる。

| 系統 | 特徴 | 向いている作業 |
|---|---|---|
| Haiku | いちばん速く、いちばん安い | 量が多い作業、すぐ答えが要る作業（分類、抽出、振り分け）。簡単な調べもの |
| Sonnet | 速さと性能のバランスがいちばんよい。Claude 101 は、日常の利用者に勧めるデフォルトのモデルとしている | 日常の仕事（文章作成、データ分析、コード作成など） |
| Opus | いちばん複雑な作業向け。Sonnet より遅い | 何段階もの分析、長く続くエージェントの作業、難しい判断 |

  - 2026 年 10 月 31 日の時点の最新版は、Claude Haiku 5.5、Claude Sonnet 5.5、Claude Opus 5.5。API の料金（入力と出力の 100 万トークンあたり）は、Haiku 5.5 が 0.10 ドルから・0.50 ドルから、Sonnet 5.5 が 2 ドル・10 ドル、Opus 5.5 が 4 ドル・20 ドル。
  - このほかに、Opus より上の **Claude Fable 5.1** がある。試験ガイド（2026 年 7 月）の 3 つの系統には入っていない。
- **公式の教材と公式ドキュメント**
  - Claude 101 レッスン 2「Claudeとの最初の会話」（Opus はいちばん複雑な作業向け、Sonnet は推奨のデフォルト）。
  - 開発者向けドキュメント「Models overview」。Haiku 5.5 を「分類、抽出、振り分けのような、量が多くすぐ答えが要る作業向け」、Sonnet 5.5 を「速さと知能の最もよい組み合わせ」と説明している。
- **試験での見分け方**：問題文の言葉で系統を選ぶ。「大量」「すぐに」「安く」なら Haiku、「日常の」「バランス」なら Sonnet、「複雑」「何段階も」「正確さが費用より大事」なら Opus。
- **紛らわしいもの**：モデルの名前と番号は、新しい版が出るたびに変わる。試験では、番号ではなく系統（Haiku、Sonnet、Opus）の役割で考える。

## 項目 3　タスクの要件に合わせて、モデルを選ぶ

- **要点**
  - モデルを選ぶ観点は、**性能**（必要な能力があるか）、**速さ**、**費用**。
  - 選び方には 2 つの始め方がある。
    - **効率から始める**：Haiku で始めて試し、要件に足りないところがあるときだけ上のモデルに変える。試作、速さが要る作業、費用を抑えたい作業、量が多く単純な作業に向く。
    - **性能から始める**：Opus で始めて結果を確かめ、あとで設定を下げたり、下のモデルに変えたりして効率を上げる。複雑な推論、細かな理解が要る作業、正確さが費用より大事な作業に向く。
  - どちらでも、実際の依頼とデータで試して、正確さ、品質、例外の扱いを比べてから決める。
  - claude.ai では、入力欄の下のモデル名から選ぶ。**モデルを変えると、新しいチャットになる**。
  - 思考モードは複雑な分析に役立つが、答えが遅くなる。簡単な作業は、Sonnet で思考モードを切って始め、足りなければモデルを変えるか思考モードを入れる。
  - 使うモデルや会話の長さによって、使用量の減り方が変わる。
- **公式の教材と公式ドキュメント**
  - 開発者向けドキュメント「Choosing the right model」の「Establish key criteria」「Choose the best model to start with」。
  - Claude 101 レッスン 2 のモデルの選び方と、拡張思考モードの説明。
  - ヘルプセンター「How do usage and length limits work?」。使用量は、会話の長さと複雑さ、使うモデル、選んだ設定などで変わる、としている。
- **試験での見分け方**：「いつも最上位のモデルを使う」は、費用と時間をむだにするので正解になりにくい。作業の要件（量、速さ、正確さ）に合うモデルを選び、複雑な推論のために上位のモデルを取っておく選択肢を選ぶ。
- **紛らわしいもの**：リサーチ機能は、チャットで選んだモデルにかかわらず Opus で動く。リサーチを使うためにモデルを変える必要はない。

## 項目 4　コンテキストの制限とメモリを管理する

- **要点**
  - **コンテキストウィンドウには上限がある**。中にあるものにしか注意を向けられない。上限を超えると、うまくいっていた状態から急に機能しなくなる（崖のように落ちる）。情報が黙って切り捨てられ、いつも警告が出るとは限らない。
  - 長い資料の**途中に埋もれた大事な指示**は、見落とされやすい。大事な指示は先頭にはっきり書く。
  - Claude は、会話の中での訂正から学習しない。**新しい会話は白紙から始まる**。
  - claude.ai の有料プランのコンテキストウィンドウは、モデルによって 1M（100 万）、500K、200K トークン。最新の Haiku 5.5、Sonnet 5.5、Opus 5.5 は、チャットで 1M。
- **3 つの判断**

| 判断 | どんなときか | どうするか |
|---|---|---|
| <span class="nowrap">やり直す</span> | 会話が目的からずれた。新しい話題に移る。長い会話で使用量の上限に近い | 新しいチャットを、よりはっきりしたプロンプトで始める |
| <span class="nowrap">要約する</span> | 会話がコンテキストウィンドウの上限に近づいた | 有料プランでコード実行がオンなら、Claude が前の部分を自動で要約する。全体の履歴は残り、あとから参照できる。ただし使用量は多く減る |
| <span class="nowrap">保持する</span> | 同じ資料や指示を、何度も使う。説明し直したくない | プロジェクトのナレッジと指示に入れる。役割や好みはメモリに覚えさせる |

  - **メモリ**：会話から役割、好み、過去の決定などを覚える。Free、Pro、Max では初期設定でオン。プロジェクトごとに別のメモリを持ち、ほかのプロジェクトのメモリは使わない。シークレットチャットの内容は、メモリにも履歴にも残らない。
  - **使えるコンテキストを広げる工夫**：プロジェクトの指示は短くする。使わないツールやコネクターは切る（多くのトークンを使うため）。
- **公式の教材と公式ドキュメント**
  - AIの能力と限界「ワーキングメモリ」の「重要なポイント」。
  - Claude 101 レッスン 2「Claudeの回答を改善する」（最悪の場合は新しいチャットで再開する）と「Claudeをパーソナライズする」（メモリ）。レッスン 3「反復の考え方」（最初からやり直すタイミングを見極める）。
  - ヘルプセンター「How large is the context window on paid Claude plans?」「How do usage and length limits work?」「Use Claude's chat search and memory to build on previous context」。
- **試験での見分け方**
  - 長い会話で、前に伝えた条件が守られなくなった → 大事な点をまとめて、新しいチャットで始める。
  - 毎回同じ資料を貼っている → プロジェクトのナレッジに入れる。
  - 「前の会話で直したのに、新しい会話でまた同じ間違いをする」 → Claude は訂正から学習しないので、指示をプロジェクトの指示やメモリに残す。
- **紛らわしいもの**
  - コンテキストウィンドウ（一度に扱える範囲）と、メモリ（会話をまたいで覚える機能）は別のもの。メモリがあっても、一つの会話で扱える量は増えない。
  - 「使用量の上限」は一定の期間に使える量、「長さの上限」は一つの会話の長さで、別のもの。長さの上限が、コンテキストウィンドウに関係する。

## 確認問題

すべて自作の問題です。

<QuizQuestion
  :number="1"
  question="広報の担当者が、毎週、同じ表記ルールの資料と、過去の記事 5 本を貼り付けてから、社内報の記事を Claude に下書きさせています。同じチームの 2 人も、同じ作業をしています。最も適した方法はどれですか。"
  :choices="['毎週、新しいチャットに同じ資料を貼り付け続ける', '資料と記事をナレッジに入れ、表記ルールを指示に書いたプロジェクトを作り、チームで共有する', '毎週、リサーチ機能で記事を作らせる', '1 つのチャットを何か月も続けて使い、資料を貼り直さないようにする']"
  answer="B"
>

繰り返し使う資料、そろえたい要件、チームの共有がそろっているので、プロジェクトが合います。

- **A（誤り）**：毎回、同じ資料を説明し直しています。
- **B（正解）**：プロジェクトのナレッジと指示は、すべてのチャットで使われ、チームで共有できます。
- **C（誤り）**：多くの情報源をまとめる調査ではありません。
- **D（誤り）**：会話が長くなり、コンテキストウィンドウの上限に近づきます。使用量も多く減ります。

</QuizQuestion>

<QuizQuestion
  :number="2"
  question="経理の担当者が、3 年分の決算データを使って、いくつもの段階を踏む財務分析を Claude にさせたいと考えています。量は 1 回だけで、費用より正確さが大事です。最も適したモデルの系統はどれですか。"
  :choices="['Haiku', 'Sonnet', 'Opus', 'どれでも同じなので、いちばん安いもの']"
  answer="C"
>

何段階もの複雑な分析で、正確さが費用より大事な作業です。

- **A（誤り）**：Haiku は、量が多く速さが要る作業に向きます。
- **B（誤り）**：日常の作業には向きますが、問題文はいちばん複雑な作業に当たります。
- **C（正解）**：Opus は、いちばん複雑な作業向けです。
- **D（誤り）**：系統によって、性能、速さ、費用が違います。

</QuizQuestion>

<QuizQuestion
  :number="3"
  question="Claude との長い会話で、最初に伝えた「数字は千円単位で書く」という条件が、終わりのほうで守られなくなりました。この会話の作業は、まだ続きます。適切な対応はどれですか。2 つ選んでください。"
  :choices="['大事な条件と、ここまでの結果をまとめ、新しいチャットで、条件を先頭にはっきり書いて続ける', '同じ会話で、条件を伝え直さずに続ける', '今後も同じ条件で作業するなら、プロジェクトの指示に条件を書いておく', 'Claude は会話の訂正から学習するので、一度訂正すれば、ほかの会話でも守られる']"
  answer="A,C"
>

長い会話では、前の情報に注意が向きにくくなります。新しい会話は白紙から始まり、訂正からは学習しません。

- **A（正解）**：やり直すときは、大事な点を先頭にはっきり書きます。
- **B（誤り）**：条件が守られないままです。
- **C（正解）**：繰り返し使う条件は、プロジェクトの指示に残します。
- **D（誤り）**：Claude は訂正から学習しません。今のコンテキストにあるものにだけ応えます。

</QuizQuestion>
