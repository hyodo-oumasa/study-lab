# Associate 分野 5：設定とナレッジ管理

[Associate – Foundations](./associate) の出題分野 5「設定とナレッジ管理」（Configuration and Knowledge Management）を、試験ガイドの項目ごとに見ます。比重は 12% です。

この分野は、プロジェクト、指示、資料（ナレッジ）、コネクターを設定し、内容を新しく保つための判断を問います。

## この分野の項目

試験ガイドは、この分野について 4 つの項目を挙げています。日本語版の試験ガイド（Version 1.0）の言い方に合わせ、短くまとめました。

| 番号 | 項目 |
|---|---|
| 1 | 指示とナレッジソースを使って、Claude のプロジェクトを設定する |
| 2 | アップロードしたナレッジと、コネクター（Google Drive、Gmail など）を管理する |
| 3 | 効果的なシステムレベルの指示を作る |
| 4 | 設定、ナレッジソース、指示に情報を反映し、維持し、更新する |

この分野で使う言葉です。

| 日本語 | 英語 | 意味 |
|---|---|---|
| ナレッジ（ナレッジソース） | knowledge / knowledge source | Claude に参照させる資料。プロジェクトでは、アップロードしたファイルや Google Drive の文書 |
| プロジェクトの指示 | project instructions | そのプロジェクトのすべてのチャットで、Claude がどう振る舞うかを決める指示 |
| Claude への指示 | Instructions for Claude | アカウント全体の設定。すべての会話に使われる指示 |
| システムレベルの指示 | system-level instructions | 一つひとつの依頼ではなく、会話全体の前提として与える指示。claude.ai では上の 2 つ、API ではシステムプロンプトに当たる |
| コネクター | connector | Claude を、ほかのアプリやサービス（Google Drive、Gmail、Slack など）につなぐ仕組み。MCP という共通の方式で動く |
| MCP | Model Context Protocol | AI をアプリにつなぐための、公開された共通の方式。「AI の USB-C」とたとえられる |
| スキル | skill | 決まった作業の手順を Claude に教える、指示やスクリプトをまとめたもの |

## 項目 1　指示とナレッジで、プロジェクトを設定する

- **要点**
  - プロジェクトは、専用の**チャット履歴、ナレッジ、指示、メモリ**を持つ作業場所。
  - **ナレッジ**：プロジェクトの「ファイル」に入れた資料は、そのプロジェクトのすべてのチャットで使われる。入れる資料の例は、ブランドガイドラインやテンプレートなどの参考資料、調査報告や議事録などの背景資料、まねしてほしい作業の例。
  - **指示**：そのプロジェクトのすべてのチャットに使われる。よい指示には、取り組んでいる内容のコンテキスト、進め方、トーンとスタイル、具体的な要件を入れる。
  - 会話中にアップロードしたファイルは、その会話だけで使われ、ナレッジには入らない。ナレッジを散らかさずに、一時的な資料を渡せる。
  - プロジェクトの**説明**は、Claude には見えない。説明は、自分やチームのためのもの。Claude に伝えたいことは指示に書く。
- **公式の教材と公式ドキュメント**
  - Claude 101 レッスン 5「プロジェクト入門」の「最初のプロジェクトを作成する」（ステップ 1〜3）。
  - ヘルプセンター「What are projects?」。
- **試験での見分け方**：「何を参照させるか」（資料）はナレッジ、「どう振る舞わせるか」（トーン、手順、要件）は指示、に入れる選択肢を選ぶ。
- **紛らわしいもの**
  - **プロジェクトとスキル**：プロジェクトは知識を保存し（何を）、スキルは手順を実行する（どのように）。繰り返す作業の手順を毎回同じにしたいならスキル、参照する資料をまとめたいならプロジェクト。2 つは組み合わせられる。
  - チームで共有するなら、プロジェクトを共有する（Team と Enterprise）。権限は、閲覧可能（中身を見てチャットできるが変えられない）と、編集可能（指示とナレッジを変えられる）がある。

## 項目 2　アップロードしたナレッジとコネクターを管理する

- **要点**
  - **ファイル名**をわかりやすくする。Claude はファイル名を手がかりに資料を探すので、「document1.pdf」より「Q4-2024-Brand-Guidelines.pdf」がよい。
  - ナレッジがコンテキストウィンドウの上限に近づくと、有料プランでは RAG に切り替わり、質問に関係する部分だけを取り込む（[分野 3](./associate-3-product-model-selection) の項目 1）。
  - **コネクター**を使うと、Claude がつないだサービスの中を検索し、読み、許可していれば操作もする。コピーして貼り付ける代わりに、実際のファイルやメールについて質問できる。
  - コネクターには、クラウドのサービスにつなぐ**ウェブコネクター**と、デスクトップアプリで手元のファイルやアプリにつなぐ**デスクトップ拡張機能**がある。ディレクトリにないサービスは、カスタムコネクターとして加えられる（無料のプランは 1 つまで）。
  - **Google Drive の文書をナレッジに入れる**：私用（非公開）のプロジェクトでだけできる。共有したプロジェクトでは使えない。Google ドキュメントは Drive から直接読むので、いつも最新の版が使われる。読むのは文字だけで、文書の中の画像は読まない。
  - **権限**：Claude が見られるのは、自分が見られるデータだけ。権限はサービスごとにオン・オフでき、いつでも接続を切れる。Gmail のメール送信などの操作は、初期設定では Claude が先に承認を求める。
  - **Team と Enterprise**：オーナーが先に組織でコネクターを有効にする。有効にしても、メンバーは一人ひとり自分のアカウントで認証する。オーナーは操作ごとに「常に許可」「承認が必要」「禁止」を決められ、メンバーはそれを変えられない。
- **公式の教材と公式ドキュメント**
  - Claude 101 レッスン 5「プロジェクト入門」の「ステップ3：ナレッジベースを構築する」と、そのプロのヒント（ファイル名）。
  - Claude 101 レッスン 8「ツールを接続する」の「主なポイント」「ウェブコネクタの設定」「セキュリティと権限」。
  - ヘルプセンター「Use connectors to extend Claude's capabilities」「Use Google Workspace connectors」。
- **試験での見分け方**：「最新の版を使いたい」「資料が Drive にある」なら、ファイルをアップロードし直すより、Google Drive から入れる選択肢を選ぶ（私用のプロジェクトの場合）。「ほかの人のメールも見られる」のような選択肢は誤り。
- **紛らわしいもの**
  - コネクターをつなぐと、依頼で**指し示せる場所**が増える。ただし、つないだだけで Claude が毎回そこを探すとは限らない。「Google Drive の関連する資料も見て」のように、依頼の中で指し示す。
  - コネクターから取り出したデータは、その会話と一緒に Anthropic のサーバーに保存され、会話を消すと消える。Gmail、Drive、カレンダーのコネクターのデータは、モデルの学習に使われない（個人向けのプランで学習を許可していて、内容を会話に写した場合などを除く）。

## 項目 3　効果的なシステムレベルの指示を作る

- **要点**
  - 指示には、**全体のコンテキスト、大事な決まり、Claude の役割**を書く。短く保つ（長い指示は、コンテキストウィンドウを使う）。
  - **理由を添える**。理由が分かると、Claude は決まりの意図を広げて当てはめられる。
  - **してほしいことで書く**（「〜しないで」より「〜にして」）。
  - **役割**を一文で与えるだけでも、振る舞いとトーンがその用途に絞られる。
  - 指示で作業を自動化することもできる。たとえば「議事録をアップロードしたら、このテンプレートで要約を作って」。
  - **どこに書くか**：

| 書く場所 | 効く範囲 | 向いているもの |
|---|---|---|
| Claude への指示（アカウント） | すべての会話 | どの作業でも変わらない好み（言葉づかい、答えの形など） |
| プロジェクトの指示 | そのプロジェクトのチャットだけ | そのプロジェクトの目的、手順、トーン、要件 |
| スキル | 必要なときに呼び出される | 決まった作業の手順 |

- **公式の教材と公式ドキュメント**
  - Claude 101 レッスン 5 の「ステップ2：プロジェクト指示を追加する」。Claude 101 レッスン 2 のプロのコツ（「Claudeへの指示」はすべての会話に使われる）。
  - ヘルプセンター「How large is the context window on paid Claude plans?」（プロジェクトの指示は、プロジェクトの全体のコンテキスト、大事な決まり、Claude の役割を書き、短くする）。
  - ヘルプセンター「Understanding Claude's personalization features」（アカウント全体の指示、プロジェクトの指示、スキルの範囲の違い）。
  - 開発者向けドキュメント「Prompting best practices」の「Give Claude a role」「Add context to improve performance」。
- **試験での見分け方**：「すべての会話で」ならアカウントの指示、「このプロジェクトでだけ」ならプロジェクトの指示を選ぶ。決まりを並べるだけの指示より、目的と理由のある指示を選ぶ。
- **紛らわしいもの**：指示を強い言葉で繰り返しても、意図は伝わらない。守られないときは、目的を書き足す（[分野 7](./associate-7-troubleshooting) の項目 1）。

## 項目 4　設定とナレッジを維持し、更新する

- **要点**
  - **使わなくなったファイルは消す**。古い資料が残ると、Claude が古い情報を参照する。ナレッジが小さいほど、使えるコンテキストも増える。
  - **方針が変わったら、指示とナレッジを直す**。Claude は会話の中での訂正から学習しないので、続けて守ってほしいことは、指示やナレッジに入れて残す。
  - 何度も同じことを説明し直しているなら、それを**常設のコンテキスト**（プロジェクトの指示、ナレッジ、メモリ）に移す。
  - **メモリ**の中身は、設定から見て、直し、消せる。チャットで「これを覚えて」「これを忘れて」と頼むこともできる。プロジェクトのメモリは、プロジェクトごとに分かれる。
  - スキルは、Claude に頼んで直してもらえる。
  - 使わないツールやコネクターは切る。多くのトークンを使うため。
- **公式の教材と公式ドキュメント**
  - ヘルプセンター「How do usage and length limits work?」（使わないファイルを消す、プロジェクトの指示を短くする、ツールとコネクターは多くのトークンを使う）。
  - ヘルプセンター「Use Claude's chat search and memory to build on previous context」（メモリの確認、編集、削除）。
  - AIの能力と限界「ワーキングメモリ」（モデルは訂正から学習しない。常設のコンテキストが要るタスクを見分ける）。
  - Claude 101 レッスン 7「スキルを活用する」の「カスタムスキルの作成」。
- **試験での見分け方**：「古い料金表の内容で答える」「改定前の規程で答える」なら、ナレッジの古いファイルを消して新しい版に入れ替える選択肢を選ぶ。
- **紛らわしいもの**：チャットで「新しい規程を使って」と伝えるだけでは、ほかのチャットには伝わらない。プロジェクトのナレッジを入れ替える。

## 確認問題

すべて自作の問題です。

<QuizQuestion
  :number="1"
  question="営業チームのプロジェクトを作ります。「価格表と製品資料を参照させたい」「答えは必ず敬語で、最後に次の行動を書いてほしい」の 2 つを設定したいとき、正しい組み合わせはどれですか。"
  :choices="['どちらもプロジェクトの説明に書く', '価格表と製品資料はナレッジに入れ、敬語と次の行動は指示に書く', '価格表と製品資料は指示に貼り付け、敬語と次の行動はナレッジに入れる', 'どちらも、チャットのたびに最初のメッセージで伝える']"
  answer="B"
>

参照させる資料はナレッジ、振る舞いは指示に入れます。

- **A（誤り）**：プロジェクトの説明は、Claude には見えません。
- **B（正解）**：何を参照するかはナレッジ、どう振る舞うかは指示です。
- **C（誤り）**：役割が逆です。資料を指示に貼ると、指示が長くなります。
- **D（誤り）**：毎回の説明が要らないように、プロジェクトに設定します。

</QuizQuestion>

<QuizQuestion
  :number="2"
  question="プロジェクトで、4 月に改定された経費規程について聞いたところ、Claude が改定前の金額で答えました。最も適切な対応はどれですか。"
  :choices="['チャットで「新しい規程を使って」と伝え、ほかのチャットでも守られることを期待する', 'ナレッジから古い規程を消し、改定後の規程を入れる', 'プロジェクトの指示に「必ず正しく答えること」と強く書く', 'モデルを上位のものに変える']"
  answer="B"
>

古い資料がナレッジに残っていると、Claude はそれを参照します。

- **A（誤り）**：Claude は訂正から学習しません。ほかのチャットには伝わりません。
- **B（正解）**：ナレッジを新しい版に入れ替えます。
- **C（誤り）**：強い言葉にしても、古い資料が参照されることは変わりません。
- **D（誤り）**：資料が古いことは、モデルを変えても直りません。

</QuizQuestion>

<QuizQuestion
  :number="3"
  question="Team プランの会社で、Google Drive のコネクターについて正しい説明はどれですか。2 つ選んでください。"
  :choices="['オーナーが組織でコネクターを有効にすれば、メンバーは認証しなくても使える', 'Claude が読めるのは、そのメンバー自身が見られるファイルだけである', 'Google ドキュメントを私用のプロジェクトのナレッジに入れると、Drive から直接読むので、最新の版が使われる', 'コネクターをつなぐと、Claude は会社の全員の Drive のファイルを読めるようになる']"
  answer="B,C"
>

- **A（誤り）**：オーナーが有効にしても、メンバーは一人ひとり自分のアカウントで認証します。
- **B（正解）**：Claude が見られるのは、自分が見られるデータだけです。
- **C（正解）**：Google ドキュメントは Drive から直接読まれます。共有したプロジェクトでは、Drive から入れられません。
- **D（誤り）**：B と同じ理由で、ほかの人のファイルは読めません。

</QuizQuestion>
