# Claude Code を使う場所

Claude Code は、ターミナル、デスクトップアプリ、VS Code などのエディター、ブラウザー、スマートフォンから使えます。どこから使っても、裏で動いている仕組み（[01. Claude Code とは何か](./01-what-is-claude-code) で説明したエージェントのループ）は同じです。違うのは、操作する画面と、使える機能の範囲です。このページでは、その違いと、何が共有されるのかを整理します。

## この記事で分かること

- Claude Code を使える場所の種類と、それぞれが向いている場面
- 「コードが実行される場所」と「操作する画面」を分けて考える方法
- Claude Code の本体が、使う場所ごとに別々に入っていること
- 使う場所が違っても共有されるものと、共有されないもの
- ターミナル版でしか使えない機能

## 用語の整理

| 用語 | 意味 |
|---|---|
| ターミナル（terminal） | 文字でコマンドを入力して、PC を操作する画面 |
| CLI（command-line interface） | ターミナルで、コマンドを入力して使う形のソフトウェア。Claude Code のターミナル版は、`claude` というコマンドで起動する |
| IDE（integrated development environment） | コードの編集、実行、デバッグなどを 1 つにまとめた開発用のソフトウェア。VS Code や JetBrains の製品など |
| 拡張機能（extension） | IDE に機能を追加する部品 |
| ローカル（local） | 自分の PC の上で動かすこと |
| クラウド（cloud） | インターネットの先にある、サービス提供者の環境で動かすこと |
| Remote Control | 自分の PC で動いているセッションを、ブラウザーやスマートフォンなど、別の機器から操作する機能 |
| Dispatch | スマートフォンのアプリから作業を送り、自分の PC のデスクトップアプリで実行させる機能 |

## 使える場所の一覧

公式ドキュメントは、Claude Code を使える場所を、次の 6 つに分けています。

| 場所 | 向いている場面 | 特徴 |
|---|---|---|
| ターミナル（CLI） | ターミナルでの作業、スクリプトからの自動実行、画面のない遠隔のサーバー | すべての機能が使える |
| デスクトップアプリ | 変更内容を見た目で確認したい。複数のセッションを並行して進めたい | 変更の差分の表示、作ったアプリやページのプレビュー |
| VS Code | VS Code の中で、ターミナルに切り替えずに使いたい | エディター上での差分の表示、開いているファイルや選択範囲の共有 |
| JetBrains | IntelliJ、PyCharm、WebStorm など、JetBrains の IDE の中で使いたい | 差分の表示、選択範囲の共有 |
| Web（claude.ai/code） | 細かく指示しなくてよい、時間のかかる作業。PC を閉じても続けたい作業 | クラウドで動く。接続を切っても作業が続く |
| スマートフォン | PC から離れているときに、作業を始めたり、進み具合を見たりしたい | クラウドのセッションの操作、Remote Control、Dispatch |

公式ドキュメントは、この違いを、次のように説明しています。

- ターミナル版は、最も機能がそろっている。スクリプトからの実行などは、ターミナル版だけで使える。
- デスクトップアプリと IDE の拡張機能は、ターミナル版だけの機能の一部と引き換えに、見た目での確認や、エディターとの連携を得ている。
- Web はクラウドで動くので、接続を切っても作業が続く。
- スマートフォンは、クラウドのセッションや、Remote Control でつないだ自分の PC のセッションを操作するための、窓口にあたる。

1 つのプロジェクトに対して、複数の場所を組み合わせて使えます。

## 2 つの軸で整理する

使える場所は、「コードが実行される場所」と「操作する画面」の 2 つに分けて考えると、整理しやすくなります。

### コードが実行される場所

| 実行される場所 | 内容 |
|---|---|
| 自分の PC（ローカル） | 自分の PC のファイルを直接読み書きし、自分の PC に入っている道具でコマンドを実行する |
| クラウド | 既定では、Anthropic が管理する環境で動く。アプリやブラウザーを閉じても、作業が続く |
| 遠隔のマシン | 自分が管理するサーバーなどに接続して、その上で動かす |

### 操作する画面と、実行される場所の組み合わせ

| 操作する画面 | 自分の PC で実行 | クラウドで実行 |
|---|---|---|
| ターミナル | できる（標準の使い方） | クラウドのセッションへ作業を移せる |
| デスクトップアプリ | できる（セッションを始めるときに「Local」を選ぶ） | できる（「Cloud」を選ぶ） |
| VS Code の拡張機能 | できる（標準の使い方） | claude.ai のクラウドのセッションを再開できる |
| Web（claude.ai/code） | Remote Control で、自分の PC のセッションを操作できる | できる（標準の使い方） |
| スマートフォン | Remote Control と Dispatch で、自分の PC に作業をさせられる | できる（標準の使い方） |

デスクトップアプリでは、セッションを始めるときに、実行する環境（Local、Cloud、SSH での接続先など）、プロジェクトのフォルダー、モデル、権限モードの 4 つを選びます。

「どの画面で操作しているか」と「どこでコードが動いているか」は、別のことです。たとえば、スマートフォンから操作していても、Remote Control であれば、コードが動いているのは自分の PC です。ファイルがどこにあり、コマンドがどこで実行されるのかは、権限や安全性を考えるときの前提になります。

## 本体は、使う場所ごとに別々に入っている

ターミナル版、デスクトップアプリ、VS Code の拡張機能は、どれも同じ Claude Code を動かしています。ただし、その本体は、使う場所ごとに別々に入っています。

| 使う場所 | Claude Code の本体 |
|---|---|
| ターミナル版 | 自分でインストールしたもの |
| デスクトップアプリ | アプリが、自分用にダウンロードして、更新するもの |
| VS Code の拡張機能 | 拡張機能に含まれているもの |

そのため、同じ PC の中でも、使う場所によって、Claude Code のバージョンが違うことがあります。公式ドキュメントにも、デスクトップアプリの本体と、ターミナル版の本体は、片方を更新しても、もう片方は更新されないと書かれています。

新しい機能には、「バージョン〇〇以降で使える」という条件が付いていることがあります。ある場所で使える機能が、別の場所では使えないときは、まず、その場所のバージョンを確かめます。

このサイトの作業では、はじめはデスクトップアプリだけを使っていました。その後、[08. MCP サーバーを自作する](./08-build-an-mcp-server) の作業のために、ターミナル版も入れました。入れた時点で、デスクトップアプリの Claude Code は 2.1.295、ターミナル版は 2.1.300 で、実際にバージョンが違っていました。

### バージョンの確かめ方

| 使う場所 | 確かめ方 |
|---|---|
| ターミナル版 | ターミナルで `claude --version` を実行する |
| デスクトップアプリ | セッションの中で `/status` と入力して、「Claude Code」の行を読む |

## 共有されるもの、共有されないもの

自分の PC で使う場合、使う場所が違っても、同じ設定ファイルを読みます。そのため、一度用意した設定は、ほかの場所でもそのまま使えます。

| 項目 | 置き場所 | ターミナル版、デスクトップアプリ、VS Code の拡張機能での扱い |
|---|---|---|
| プロジェクトのルール | プロジェクトの `CLAUDE.md` | 共有される |
| 設定（権限のルール、環境変数など） | `~/.claude/settings.json` など | 共有される |
| MCP サーバー（外部のツールとつなぐ仕組み）の設定 | `~/.claude.json`、プロジェクトの `.mcp.json` | 共有される |
| フック、スキル | 設定ファイルやプロジェクトの中 | 共有される |
| 会話の履歴 | 自分の PC の中 | VS Code の拡張機能とターミナル版は、同じ履歴を使う。デスクトップアプリとターミナル版は、セッションの一覧は別々だが、ターミナル版のセッションをデスクトップアプリで再開できる |
| Claude Code の本体と、そのバージョン | それぞれの場所 | 共有されない |

権限のルールが共有される点は、設定を考えるうえで大切です。`~/.claude/settings.json` に書いた権限のルールは、デスクトップアプリのセッションにも、VS Code の拡張機能にも適用されます。権限と設定は、「03. 権限モードと、確認を減らす方法」と「04. 設定ファイルの仕組み」で扱う予定です。

1 つだけ、共有のしかたが違うものがあります。デスクトップアプリのチャット用の設定ファイル（`claude_desktop_config.json`）に書いた MCP サーバーは、デスクトップアプリの中では使えますが、ターミナル版は、このファイルを読みません。

## ターミナル版でしか使えないもの

デスクトップアプリで使えない機能として、公式ドキュメントが挙げているものから、このテーマに関係するものを抜き出します。

| 機能 | デスクトップアプリでの扱い |
|---|---|
| スクリプトからの実行、自動化への組み込み | 使えない |
| Agent Teams（複数の Claude に役割を分けて、協力させる機能） | 使えない。ターミナル版で使う |
| ターミナルの中に設定用の画面を開くコマンド（`/permissions` など） | 使えない、または動きが違う。`/permissions` は「この環境では使えない」と表示される。`/config` は、アプリの設定画面を開く。権限のルールなどは、設定ファイルを直接編集する |
| 権限モードの `dontAsk` | 選べない |

VS Code の拡張機能については、公式ドキュメントに、次の違いが挙げられています。

| 機能 | ターミナル版 | VS Code の拡張機能 |
|---|---|---|
| コマンドとスキル | すべて使える | 一部が使える |
| MCP サーバーの設定 | できる | できる |
| チェックポイント | 使える | 使える |
| `!` で始めて、シェルのコマンドを直接実行する | できる | できない |

逆に、デスクトップアプリにあって、ターミナル版にないものもあります。画像や PDF の添付、Dispatch との連携などです。

## 使い分けの目安

公式ドキュメントの説明をもとにした、目安です。

| やりたいこと | 向いている場所 |
|---|---|
| 変更内容を見た目で確認しながら進めたい。作ったページを、その場で表示して確かめたい | デスクトップアプリ |
| 複数の作業を、1 つの画面で並行して進めたい | デスクトップアプリ |
| VS Code でコードを開いたまま、同じ画面で頼みたい | VS Code の拡張機能 |
| スクリプトや、自動実行の仕組みの中から呼び出したい | ターミナル版 |
| Agent Teams を使いたい | ターミナル版 |
| 時間のかかる作業を任せて、PC を閉じたい | Web（クラウド） |
| 外出先から、作業を始めたり、進み具合を見たりしたい | スマートフォン |

どれか 1 つに決める必要はありません。設定とプロジェクトのルールは共有されるので、普段はデスクトップアプリを使い、必要になったときにターミナル版を加える、という使い方ができます。

## まとめ

- Claude Code は、ターミナル、デスクトップアプリ、VS Code、JetBrains、Web、スマートフォンから使える。裏で動いている仕組みは同じで、操作する画面と、使える機能の範囲が違う。
- 「どの画面で操作しているか」と「どこでコードが動いているか」は、分けて考える。
- Claude Code の本体は、使う場所ごとに別々に入っていて、更新も別々に行われる。バージョンが違うことがある。
- 自分の PC で使う場合、設定、プロジェクトのルール、MCP サーバーの設定は、使う場所が違っても共有される。
- スクリプトからの実行、Agent Teams、`/permissions` などの設定用の画面は、ターミナル版で使う。
